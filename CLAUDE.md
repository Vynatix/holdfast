# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Holdfast — transactional state containers for Kotlin Multiplatform (Maven group `com.vynatix`). Three-layer naming, all intentional: the **brand/repo/artifacts** are `holdfast*`, the **package** is `com.vynatix.holdfast`, but the **central class** is `Store<Self : Store<Self>>` (renamed Vault → Holdfast → Store; see `.git-blame-ignore-revs`). New code and docs use `Store*` class names; "holdfast" stays in artifact/package/brand names.

Targets: Android, JVM, iosArm64 + iosSimulatorArm64, wasmJs (wasmJs only on `:holdfast`, `:holdfast-coroutines`, `:holdfast-compose`). JDK 21, Kotlin 2.3.21, Gradle 9.5.

## Commands

```bash
./gradlew check                      # everything CI gates: tests, apiCheck, detekt, ktlintCheck
./gradlew :holdfast:jvmTest --tests "com.vynatix.holdfast.TransactionTest"   # one class
./gradlew :holdfast:jvmTest --tests "*.TransactionTest.someMethod"           # one method
./gradlew detekt ktlintCheck         # static analysis; format with: ./gradlew ktlintFormat
./gradlew :<module>:detektBaseline   # re-pin detekt baseline after deliberate cleanups
./gradlew apiDump                    # after ANY public-API change; commit <module>/api/* dumps
./gradlew :holdfast:dokkaGenerate    # docs (Dokka V2 — `dokkaHtml` no longer exists)
./gradlew publishToMavenLocal -Pholdfast.version=0.1.0
```

Per-target test tasks: `jvmTest`, `testAndroidHostTest` (AGP-KMP host-test naming — not `testDebugUnitTest`), `iosSimulatorArm64Test` (macOS host only). wasmJs test tasks are force-disabled on `:holdfast`/`:holdfast-coroutines` (tests use `runBlocking`/`newSingleThreadContext`, absent on wasm) and never run in CI.

Lint gotchas: detekt findings are baselined per module (`<module>/detekt-baseline.xml`) — rules stay active for new code. Files using K2 `context(name: Type)` syntax are excluded from ktlint (it can't parse them): `BoxedHandle.kt`; new context-parameter files need the same per-module `ktlint { filter { exclude(...) } }` treatment. `Store` sits at detekt's `LargeClass` limit: add new `Store` surface as extensions in their own files (as `StoreAttachments.kt` does), or move helpers out — never by re-baselining. Do NOT add `context(scope: CoroutineScope)` overloads next to default-param forms: inside any coroutine body the implicit `CoroutineScope` receiver satisfies the context parameter and silently captures the ambient scope (the `asStateFlow`/`bridge`/`suspendingBridge` overloads were removed for exactly this — issue #5).

CI (`.github/workflows/ci.yml`, push/PR to main) runs per module: `jvmTest` + `testAndroidHostTest` + `apiCheck` + `dokkaGenerate` + detekt/ktlint on ubuntu, `iosSimulatorArm64Test` + `jvmTest` on macos-15. **Known broken as written (verify before trusting/copying):** publish.yml calls `publishAndReleaseToMavenCentral` (vanniktech plugin — not applied anywhere; the build's own task is `publishAllPublicationsToSonatypeRepository`).

The hallmark modules (`:holdfast-hallmark`, `:holdfast-hallmark-coroutines`) are excluded from the default build because their `com.vynatix:hallmark*:0.1.0` deps only resolve via `mavenLocal()`. To include them, build/publish the sibling [hallmark repo](https://github.com/vynatix/hallmark) to `~/.m2` first, then run Gradle with `-Pholdfast.includeHallmark=true` (CI does exactly this). The `shouldBeBoxedAs` matcher lives in `:holdfast-hallmark`, not `:holdfast-testing`, for the same reason.

## Core architecture (`holdfast/src/commonMain/.../holdfast/`)

The unit of consistency is the transaction; everything below is contractual, not incidental:

- **States are declared eagerly, materialized lazily**: `val x by state { init }` declares `x` at construction through `StateDelegate.provideDelegate` (a `StateDeclaration` in the store's `StateRegistry`, in declaration order; no user code runs). The `MutableState` is materialized from the retained initializer on first need — first delegate read, `snapshot()` (which materializes every declared state, so snapshots are complete), `reset()` (likewise, before its transaction opens), `restore()` (its targets — plus every `StateTag.Remote` state when sterile — before its action opens) or `taggedStates(tag)`. `properties`/`getState`/`hasState` show materialized states only; `removeState`/`clearStates` keep declared states' declarations, `dispose()` drops all. A name is declared once per store: a second declaration fails fast unless it re-runs the same site (same member `KProperty`, or a local delegated property of that name — one predicate, `DeclarationSite.isSameSiteAs` in `StateDeclaration.kt`, shared by `StateRegistry.repeats` and `KeyedRegistry.declare` and carrying the Kotlin/Native local-property caveat). A delegate wrapping `state(…)` must forward `provideDelegate` (see `BoxedHandleDelegate`). Initializers run behind a per-declaration latch outside `propertiesLock` (but under any lock their caller holds), read committed values only (except when `reset()` or a sterile `restore()` re-runs them; see the reset bullet), may not write (`NoWriteRegion`: every write entrypoint throws), and cycles throw (`InitializerGraph`) instead of deadlocking; a throwing initializer stays retryable. `derived`/`suspendDerived` backings are `StateKind.DerivedBacking` (`registerDerivedBackingState`): captured by `snapshot()`, hidden from `stateNames`/`size`, restored only into the same instance (`originKey == lockOrderKey`) and never by a sterile restore.
- **`store action { }` buffers, never writes**: the whole action (including observer fanout) runs under the store's `transactionLock` (a reentrant spin-yield `StoreLock` — a slow observer blocks every other action on that store). `mutate` stages post-`Transformer.set` raw values into `Transaction.pendingWrites`. The owner thread gets read-your-own-writes through the savepoint chain (except inside a state initializer, a `SchemaVersioned.migrate` or a `derivedState`/`merged` recompute's compute — any open `NoWriteRegion` frame — which reads committed values only; an initializer re-run by `reset()` reads its own store's reset values, and one re-run by a sterile `restore()` reads re-run states at reset values and other declared states at transaction-visible values); other threads only ever see committed values. Nested actions are savepoints (inner commit merges into parent; outer rollback discards all).
- **Rollback never touches state and never re-runs `Transformer.set`** — load-bearing for asymmetric transformers (encryption). Same reason snapshots hold raw values, `restore()` goes through `stagePendingRaw` (re-routing it through `mutate` would double-encrypt), and `reset()` stages initializer output raw (initial values are stored without `Transformer.set`).
- **`reset()` (experimental, `Reset.kt`) re-runs retained initializers as one action** (id `Reset`; a savepoint inside an action, part of the frame inside `atomic`). It materializes every declared state first, then `stageResetOfDeclaredStates(txn)` installs a `ResetPass` on `Transaction.pendingReset` and resolves `StateKind.Declared` states in declaration order (derived backings and internal states are never reset; derived states recompute after the commit). A re-run initializer (`NoWriteRegion.runForReset`, no latch, under the reset's locks) reads its own store's declared states at their reset values via `ResetPass.valueFor` (fresh-store first-read order; a still-running one is a cycle) and everything else at committed values; it still may not write. Output is staged raw and only where it differs (`==`) from the transaction-visible value, so unchanged states never fire, even with `distinct = false`. `stageResetOfDeclaredStates` also stages straight into `atomic` frame roots (the #21 `reset(node)` shape); after the declared states, `ResetPass.addLiveKeyedEntries` adds every keyed entry live in the transaction's view (an entry that comes to life during the pass is reset too; the pass never evicts, and an entry its chain evicts is never staged); `ResetPass.notifyAttachments` tells the store's attachments (see the attachments bullet). A sterile `restore()` runs the same pass after staging its writes (`stageResetOfRemoteStates`, `readsStagedWrites = true`, attachments not notified) over the Remote states, Remote keyed families' live entries, and the declared states and keyed entries the restore brought to life (`RestorePlanner.cameToLife`); every state a pass resolves is pinned in `Transaction.resetHeld`, so `removeState`/`clearStates` refuse it until the root ends.
- **Keyed state families** (#20 R7, experimental; `Keyed*.kt`): `val docs by keyedState<K, T> { key -> … }` declares a family sharing the store's names with states; entries are `StateKind.Keyed` declarations kept by the family (never in `properties`), created by `docs[key]` through the declared-state latch/`NoWriteRegion`/cycle detection (creation is not a write and is not bracketed). `evict`/`evictAll` stage into `Transaction.evictions` (under `pendingLock`, disjoint from `pendingWrites`; the last operation on an entry wins, merged on savepoint commit; inside a suspending body only a write cancels a staged eviction, never a `get`). The apply pass retires (`MutableState.retired`) and unlinks evicted entries INSIDE its write bracket; the fanout shuts them down before any observer; a retired entry is a stale handle and every write entrypoint (the `bridge` setter included) throws. An eviction from the store's own commit fanout is the one write that defers (D16): a `DeferredEviction` post-commit task through `tryTopLevelAction`. `captureConsistent` lists entries unbracketed and re-lists when membership moved (after 4 attempts it holds entry creation back on other threads around its listing + cut, which must stay free of user code). The `@StoreInternalApi` membership listener (for #21) sees one entry's Added strictly before its Evicted; track entries by identity. Keys never appear in messages/`toString`/middleware (`docs[*]`); only a snapshot's `encode()`/`render()`/`keysOf` show them.
- **Store attachments** (`StoreAttachments.kt`, `@StoreInternalApi`; the slot PR 13's hydrator and #21's tree membership attach through): library machinery bound to one store's life, one per identity-compared `StoreAttachmentKey`, in attach order, in an `AttachmentSlot` independent of the state registry — a base class's `init` can attach before subclass states are declared, so an attachment resolves declarations lazily. `internalAttachIfAbsent` has one winner under races and runs `create` under the slot lock, ordered `transactionLock` → `middlewareLock` → `pendingLock` → initializer latch → slot lock → `propertiesLock` → per-state locks: `create` may build the attachment, call `registerInternalState` or attach under another key, but must not open an action or frame, call `reset`/`restore`/`dispose`, first-read a state or touch another store. Lookups are lock-free and answer empty after dispose. `reset()` calls `onStoreReset` inside its transaction after staging and outside `NoWriteRegion` (its writes join the reset; a throw rolls it back; a sterile `restore` tells none). `dispose()` closes the slot under `transactionLock`, then, as its last step, calls each `onStoreDisposed` once, holding no lock `dispose()` took (but any its caller holds).
- **Snapshots leave memory through codecs; `restore` plans, then stages** (#20 R1; experimental except `StateCodec`). `StateCodec` (root, stable; `bridge.Codec` extends it) encodes a state's RAW value; it lives on `StateDeclaration.codec`, set only by the `@ExperimentalStoreApi` `state(transformer, distinct, codec, tags, initialize)` overload — calls passing neither `codec` nor `tags` must keep resolving to the frozen 3-arg `state` (guarded by `StableStateOverloadTest`, in a no-opt-in file). `StoreSnapshot` wraps `CapturedContent` (raw values; `entry`/`get` by state instance, guarded by `originKey`) or `DecodedContent` (read by name through the reading state's codec); reads resolve through `MutableState.declaration` and work after dispose. The v1 wire body (`SnapshotEnvelope.kt`, embeddable verbatim) is canonical; the reader caps nesting at 64 and skips unknown fields; an object value under `states` is a keyed state family, strictly `{encodedKey: text|null}` (key via the family's `keyCodec`, value via its `codec`, `null` = withheld), written sorted by encoded key. `RestorePlanner` runs BEFORE the action opens (materializes targets, runs codec `decode`, the type witness and `RestorePolicy`; the frozen 1-arg `restore` uses `IgnoreUnknown`); the action (id `Restore`) then throws any planned failure inside itself, or stages raw via `stagePendingRaw`, re-resolving each target (a concurrently dropped Declared target is re-materialized; a keyed entry evicted since the plan is created again; a dropped derived backing is skipped). Plan and stage are one `PlannedRestore`; the internal `restoreInOneFrame(snapshots, policy)` (`OneFrameRestore.kt`, for #21's `Root.restore`) plans every store, then stages each plan raw into its root of ONE outermost `atomic` (all-or-nothing, one write bracket); it refuses to run inside any entry or no-write region until mixed-frame nesting is fixed. Equality is by value (captured vs captured, decoded vs decoded; `equalsEncodable` relates the two). No exception may carry a state value.
- **Schema versions gate `restore` first** (#20 R2; experimental). A store opts in by implementing `SchemaVersioned` (never a `Store` member — #21 T2); `StoreSchema` reads `schemaVersion` once per `snapshot()`/plan and requires >= 1 (a non-versioned store is 1; `encode` writes it as `schema`). `RestorePlanner.plan()` checks it before materializing or decoding anything: same version → as is; an older DECODED body → `migrate(from, EncodedSnapshotView)` on a copy, inside `NoWriteRegion` as a `MigratingFrame` (reads committed values, every store write throws); a newer snapshot, a captured one of another version, or a throwing `migrate` → `SnapshotMigrationException`, nothing changed. Never chain `migrate`'s own exception (it may quote values).
- **Tags are policy on the declaration; Secret values are withheld when read out, never in memory** (#20 R3; experimental). `StateTag` (`Secret`, `UserAuthored`, `Remote`; closed, not exhaustive) lives on `StateDeclaration.tags`; `validateTags` refuses `Secret`+`UserAuthored` and `UserAuthored`+`Remote` at declaration; a derived backing is `Secret` only when one of its listed `sources` is. `State.tags`/`Store.taggedStates` are THE lookup every tag-driven feature uses. Captures hold a Secret's raw value (undo stays lossless); `entry` returns `Redacted` (so `get` returns `null`) unless the capture's scope is `SnapshotScope.Raw`; `encode()` writes `null` in every scope (the codec never sees it) and omits Remote states unless `includeRemote`; a captured `render()` prints `<redacted>`. Every path that records or prints a state value must withhold a Secret one — `:holdfast-testing` through `PrivilegedHooks.recordedValue`/`isSecret` (→ `@StoreInternalApi State.displayValue`), `:holdfast-hallmark`'s Secret paths through `HallmarkException(violations.withheld())`. A sterile `restore(…, sterile = true)` plans without Remote entries or derived backings, then resets Remote states in the same action (see the reset bullet).
- **Every assignment of a committed value is write-bracketed** (`MutableState.writesBegun`/`writesEnded`, `ConsistentRead.kt`): the top-level apply pass opens the bracket on every state before assigning any and closes them all after (in a `finally`) — for an `atomic`/`suspendAtomic` frame one bracket spans every top-level participant's apply pass (`applyFrameCommit`, `FrameCommit.kt`; a participant joined as a savepoint applies later, with its enclosing transaction); `applyFromBridge` brackets its single write; every apply pass bumps `KeyedRegistry.commitsApplied` before opening its bracket (a keyed capture re-lists entries only when that and a family's `createdVersion` moved). `readConsistent` takes a lock-free cut that retries while a bracket is open or has moved and never blocks a writer — `snapshot()`, `captureConsistent` and every `derivedState`/`merged` compute (`ComputeReads`) use it (legacy `derived`/`suspendDerived` computes read plain values). A new path that assigns `currentValue` must bracket it, or snapshots can tear.
- **Commit fanout order is a contract**: a commit is an apply pass then a fanout pass (`FrameCommit.kt`: `applyFrameCommit` / `Transaction.fanOutApplied`; `commitDispatching` runs both for one transaction): observers → bridge publish → event drain; within one store's fanout the SEALED states' observers (`internalSealedState`) run first, so their owner's bookkeeping sees every applied commit even when a user callback ends the fanout. A frame applies EVERY participant in one write bracket before ANY fans out, then fans each out in lock order, `FrameObserver.onFrameCommitted` last (#20 R9): an observer finds every participant applied and its writes into any participant are refused; one participant's failed fanout doesn't stop the later ones. Between the two passes each root is applied but still Active and still `activeTransaction` (and a middleware context's `transaction`): a hand `commit()`/`rollback()` on it there is a no-op (its fanout belongs to the frame; `FrameHandCommitTest`, `SuspendFrameHandCommitTest`), and `applyBracketed` skips a root another thread's commit applied first (`root.applied`, under the shared `pendingLock`), so `applyResult` is never overwritten and each root fans out exactly once. `:holdfast-coroutines`' `suspendAction`/`suspendAtomic` interpose their suspending bridge/event phases per store via these `@StoreInternalApi` hooks; reordering breaks them.
- **Writes into a closed transaction fail loudly** (#20 D16). After its apply pass a top-level commit stays installed through fanout; `Transaction.closedToWrites` (root applied, or this transaction or an ancestor ended) refuses writes: `mutate`/`update`/`emit` throw `IllegalStateException`, and a nested `action`/`atomic` returns `TransactionResult.Error` without running its body or middleware. A savepoint whose parent is `closedToWrites` when it commits (a hand `commit()`/`rollback()` on the enclosing transaction from the nested body or its `onTransactionCompleted`) refuses to merge — `mergeIntoParent` checks under the parent's `pendingLock` before `putAll`, closes and clears the savepoint's own buffers either way, and the nested action returns `Error` (a `TransactionException` whose cause is the `appliedTransactionMessage` ISE; in a frame the refused merge fails the frame). `restore`'s `PlannedRestore.stage` checks `closedToWrites` up front and per write (`stagePendingRaw` returns `false` like `stagePendingWrite`; a keyed family's replacement goes through `stageEvictionsOrRefuse`, never the D16 deferral), so a hand-finished `Restore` transaction ends as `Error`. A hand `commit()`/`rollback()` on a transaction whose buffers are already consumed (`buffersClosed`: applied, or merged) is a no-op decided under `pendingLock`: `applyAlone` returns whether THIS call applied a top-level transaction and `commitDispatching` fans out only then; `rollback()` neither discards nor changes status. "Nested" means on the owner thread or inside the commit (`Transaction.fanoutThreadId` for the sync window, `FanoutMarkers` for suspending commits); other threads' `action`/`atomic` wait. While a suspending holder is installed, `suspendingOwner` routes every thread's bare `mutate` into its transaction (joins before the apply pass, throws after). Every `pendingWrites` write AND read goes through `pendingLock` (`findPendingValue` reads each chain level under its own lock, child before parent; `removeState`/`clearStates` hold the active chain's pending locks — `Transaction?.holdingPendingLocks` — then `registry.lock`, across the check and the drop), and a write cancels a staged keyed eviction of its state (`stagePendingWrite`/`stagePendingRaw` → `cancelStagedEviction`); a new staging path must route through them, or the apply pass retires the entry and silently discards the write. `pendingLock` sits between `middlewareLock` and the initializer latch in the lock order: the apply pass holds it while taking `registry.lock` (`KeyedFamily.unlink`) and `stateLock` (`applyCommittedValue`) and may wait on a latch there (a `distinct` state's `equals` first-reading a state), so never take `pendingLock` under a latch, `registry.lock` or a per-state lock — `MutableState.value`'s owner peek runs BEFORE `stateLock` and is skipped inside any `NoWriteRegion`.
- **Post-commit failures are never silent**: observer callbacks, fanout `Transformer.get`, bridge publishes `derived` recompute failures, deferred keyed evictions, evicted-entry shutdowns, `KeyedMembershipListener` callbacks stranded hydration refreshes (a refresh whose outcome could not be recorded; reported after the gate releases, the next `hydrate()` retries it) and persisted-overlay failures (`OverlayException`: an unappliable or oversize blob, a failing capture or `put`, a cancelled writer scope; never reported under the hydration gate) go through `Store.internalReportUncaughtFailure` — `uncaughtObserverHandler` when set, else the `platform/UncaughtFailureLog` default (stderr on JVM/Android, stdout on iOS/wasmJs). A throwing `StoreAttachment.onStoreDisposed` goes to the same handler (else its own default log line); `dispose()` ignores a handler that throws there, since `dispose()` never throws.
- **Middleware: last-registered is outermost** (its `started` fires first, `completed`/`error` last). `onTransactionCompleted` runs after the body but *before* commit — throwing there rolls back.
- **Bridges inbound (`applyFromBridge`) bypass transactions and middleware entirely** and deliberately don't re-publish (loop prevention). `mutate` outside an action synthesizes a one-shot action so middleware/observers always see committed semantics — except while a `suspendAction`/`suspendAtomic` holds the store (see the closed-transaction bullet).
- **`derived()` recomputes through `postCommit` and the internal, never-blocking `tryTopLevelAction`** (recomputing inline in the commit would mutate `pendingWrites` mid-iteration). Each derived submits ONE stable task and the queue dedups by identity, so N same-store sources in one commit recompute once; a source on another, idle store recomputes inline in that source's fanout, once per changed source (legacy `derived` keeps this per-fire recompute until 0.7.0). A busy host (active txn, or serializer/`transactionLock` taken) gets the task handed to its queue plus one retry — safe only because **every top-level holder drains after releasing** (canonical list: `Store.tryTopLevelAction` KDoc; a new holder must drain too, via `internalDrainPostCommitTasks` — a frame via `internalDrainPostCommitTasksWhenSettled`, deferred to the settle of the outermost entry). `postCommit` re-reads `_activeTransaction` after enqueueing (lost-wakeup guard), and a drain pass runs each task instance once. Every post-commit task must be a never-blocking attempt (a drain runs wherever a holder releases — a `suspendAction`'s `finally`, another store's fanout), never a blocking `action`. `atomic(vararg stores)` is in-memory 2PC, lock-ordered by per-store `lockOrderKey`.
- **The serializer's install window is closed on both sides** (`SerializerInstallWindow.kt`, which carries the proof). `Store.asyncSerializer` is installed lazily by the first `:holdfast-coroutines` suspending entry, so a blocking top-level holder (`action`, `atomic`, `tryTopLevelAction`; `reset()`/`restore()` through `action`) that read none holds `transactionLock` alone. (1) Such a holder re-reads the serializer once it holds the lock, before touching the store: `action`/`atomic` release and retake the store serializer first (`holdSerialized`); `tryTopLevelAction` answers `BusyNoTxn`. (2) Every serializer holder that installs a transaction without `transactionLock` (`suspendAction`, each newly held `suspendAtomic` participant) first waits until no thread holds that lock (`awaitLockOnlyHolders` polls `@StoreInternalApi internalTransactionLockFree()` through `backOffUntil`, suspending between tries, never holding a thread); a wait-out cancelled while holding the mutex releases it and still drains. The hydration gate waits the same way before it decides. A new blocking top-level path must re-check, and a new suspending holder must wait out, or a suspending transaction can be installed over a lock-only one and cleared by its exit. `:holdfast-testing`'s open transactions stay outside this by design.
- **`derivedState`/`merged` (experimental, #20 R6/R9; `DerivedState.kt`, `DerivedStateSupport.kt`, `ComputeReads.kt`, `SettleScope.kt`) reuse `derived`'s `DerivedRecompute`** over an unregistered `distinct` backing (`StateKind.ReadOnlyDerived`: never in snapshots/`restore`/`reset()`/`encode`/`properties`/`taggedStates`; `refuseDerivedStateWrite` makes every write entrypoint refuse it). Every observation path resolves a `State` through `@StoreInternalApi observableBacking()`. `SourceFollower` subscribes before the initial compute and arms after (a racing commit, or an initial compute that read anything uncommitted, queues one catch-up recompute). **They settle once per outermost entry**: `action`/`atomic`/`suspendAction`/`suspendAtomic`, `tryTopLevelAction`, the harness's open transactions, the outermost first-read materialization and `restore`/`restoreInOneFrame` from their plan on open or join the thread's `SettleScope` (`settling { }`; `:holdfast-coroutines`' `SettleAmbientContext` carries a suspending entry's scope across dispatch). A source commit queues the recompute into it (identity dedup); the opener's `settle()` runs after it has released everything, scope still installed so a recompute's own commit joins it: frames' deferred store drains first, then tasks lowest `settleRank` first; a task or drain one settle already ran 1,000 times is deferred, so no feedback loop spins. With no scope on the fanout thread the PR 9 routing applies (the source store's queue inside its fanout, else the host). A recompute's `compute` runs in a `ComputingFrame` (committed reads only, writes refused), reads its sources from one `readConsistent` cut, and defers only to a BLOCKING holder on this thread, never to a suspending one (it may be parked on this very thread). `merged` requires two distinct `StateKind.Declared` states of the receiver. `Store.dispose()` drains (not clears) its post-commit queue. Internally (`StoreEdges.kt`, for #21's `Root.value`) a `DerivedStateNode` also follows whole stores (`addSourceStore`/`removeSourceStore`, `derivedStateOverStores`) through the followed store's `StoreEdges` attachment (`onStoreDisposed` drops the edge): a commit changing a state that is neither `ReadOnlyDerived` nor `Sealed` or evicting an entry (told first in `fanOutApplied`), an inbound bridge write, a new keyed entry, or `removeState`/`clearStates` queues the recompute where a source change would; each add, remove or drop queues one recompute (covering a racing commit). A node's list and the store's followers change as one step under `FollowedStores.lock` (then `StoreEdges.lock`, never the reverse). An edge orders nothing in a settle, so a followed store's derived state that a compute reads belongs in `sources`.
- **Hydration** (`:holdfast-coroutines` `hydrator { base; refresh; adopt }`, #20 R8, experimental) keeps its phase in two core SEALED states (`internalSealedState`, `SealedStates.kt`: unregistered, `distinct`, refused by every write entrypoint via `refuseUnwritable`, inbound bridge values dropped, never captured/restored/reset/listed; only the owner stages it, via `internalStageSealed`). Every decision (seed, retry, adopt, failure) runs under a per-store hydration gate: the store's `MutexSerializer` taken with `tryLock` plus backoff in coroutine time (`backOffUntil`), never queued on, then lock-only holders waited out (`awaitLockOnlyHolders`) before deciding, drained after release, inside one settle scope; each decision's transaction goes through `internalTopLevelAction` (middleware chain, no serializer, no drain) and re-reads the phase under `transactionLock`. The in-flight mark commits in the deciding transaction, and the refresh launches (`CoroutineStart.ATOMIC`) only after that commits; outside the gate a refresh reads the COMMITTED phase, never `phase.value`. `hydrate()`/`awaitSettled()` fail fast inside any action, frame or suspending entry. `adopt` is a savepoint checked for Remote-only writes and evictions, with `Transaction.internalForbidStructuralWrites` refusing `removeState`/`clearStates` inside it. Only `invalidate()`/`stageInvalidate()` and `reset()` (the attachment's `onStoreReset`) go back to Detached. Hydration entrypoints have rows in `:holdfast-coroutines`' own `DisposedEntrypointTest`. The optional persisted overlay (`overlay(kv, key)`, #20 R8/R3; `Overlay*.kt`) reads its key before the gate (re-read if overtaken: `Decision.REREAD`) and restores the blob in the seed transaction after `base { }` through core's `@StoreInternalApi internalRestoreTagged` (UserAuthored only, matched after `migrate`; it REPLACES each tagged keyed family the snapshot lists); a conflated writer on `Store.scope` puts `snapshot(SnapshotScope.UserAuthored).encode()` after every non-seed commit that changes a UserAuthored state, and a blob it cannot apply is reported and never overwritten until `clearOverlay()` or a later seed applies one. Never signal the writer or report an `OverlayException` under the gate (an inline dispatcher would run the handler there and deadlock on the gate's serializer).
- **The cross-module boundary is `@StoreInternalApi`** (ERROR-level opt-in), not `internal` — companion modules opt in; everything public and *not* annotated is frozen by `apiCheck`. Every new public `Store` entrypoint must call `checkNotDisposed()` and get a row in `holdfast/src/commonTest/.../DisposedEntrypointTest.kt`; cold companion APIs (`asFlow`, `first`, …) check `isDisposed` before subscribing. Two documented no-check exceptions: `snapshotMiddleware()` (a lock-free-after-take read that answers an empty ring on a disposed store) and `internalRemoveMiddleware` (issue #21 plan PR 21-1: answers `false` instead of throwing, so a caller unwinding a store that disposed mid-teardown can tell "already gone" apart from "removed" without catching).
- **Issue #21's kernel seams (plan PR 21-1, decisions U3/U12; no production consumer yet)**: `Store`/`EventfulStore` each gain a protected `@ExperimentalStoreApi` secondary constructor taking a `StoreMembership<Self>` — `abstract class StoreMembership<S : Store<S>> internal constructor()`, mintable only inside `:holdfast` — whose `bind(store)` runs once, after every field above it (and, for `EventfulStore`, its own `events`) has initialized and before any subclass property initializer or delegated state; the frozen no-arg constructors are byte-identical. A store's middleware chain is now two lists: the consumer-registered one (`middlewares`/`clearMiddleware`, unchanged) and a library-owned outer ring (`OuterMiddlewareRing`, `@StoreInternalApi internalSetOuterMiddleware`/`internalRemoveMiddleware`) that `snapshotMiddleware()`/the action chain append after it, so the ring is always outermost; `clearMiddleware()` never reaches it, `dispose()` clears both. `@StoreInternalApi internalDetach` releases one `StoreAttachment` by key before the store disposes.
- **wasmJs is single-threaded by assumption**: `currentThreadId()` returns `0` for everyone there — any new thread-identity logic must tolerate this. Expect/actual pairs live in `platform/Threading`, `platform/FrameLocal` (frame- and fanout-marker slots), `platform/StoreThreadLocals` (the no-write-region slot `NoWriteRegion` reads: running initializers, `SchemaVersioned.migrate` frames and derived-state `ComputingFrame`s; a plain global on wasmJs), `platform/SettleLocal` (the settle-scope and compute-reads slots), `platform/UncaughtFailureLog` and `bridge/FileSystemKvStore`, plus `:holdfast-coroutines`' `FrameMarkerContext` and `SettleAmbientContext` — on iOS/wasmJs, which have no `ThreadContextElement`, these carry their slot through `slotBracketingInterceptor`, an interceptor standing in for the dispatcher that MUST forward the dispatcher's `Delay` when it has one, or every `delay`/`withTimeout` inside an entry runs on real time (`SettleScopeInterceptedTest` exercises that carrier on the JVM) — (custom intermediate source sets `jvmAndAndroidMain`/`jvmAndAndroidHostTest` share JVM+Android actuals).
- `Store.Companion.defaultScope` is CAS-settable **once per process** — setting it in a test poisons every later test in that process.
- **`Store.clock` (`@ExperimentalStoreApi`) resolves like `scope`**: subclass getter override → `bindClock(Clock?)` binding → `Clock.System`. Store code reads time through `clock.now()`; library timestamps (`Transaction.endTime`, Timing/ProfilingMiddleware) deliberately don't. `bindClock` calls `checkNotDisposed()`; reading `clock` never throws.

Package layering: root kernel depends only on `platform`; `middleware/`, `bridge/`, `crypto/` are plug-ins over root contracts and never import each other. Grep trap: `middleware/HallmarkMiddleware.kt` contains `class ValidationMiddleware`. The public "vault" trio is renamed (`owningVault`→`owningStore`, `bindVault`→`bindStore`, `vaultTest`→`storeTest`); the old names survive as WARNING-level deprecated aliases for one minor — don't remove them early, and don't use them in new code. Remaining lowercase "vault" prose/internals are pre-rename residue.

## Testing harness (`:holdfast-testing`)

Entry point is `storeTest { }` (`vaultTest` is a deprecated alias; `holdfastTest` never existed — stale KDoc mentions it). Inside, `track(store)` (or an auto-registering extension used in scope, e.g. `store.read { }` / `store.timeline`; a bare `store.action { }` resolves to the `Store` member and does NOT auto-track) yields a `StoreHandle` exposing a `timeline` of `StoreEvent`s with infix matchers (`shouldFireInOrder`, `shouldHavePublished`, `shouldBeSuccess`/`shouldBeError`, …). Every `TransactionResult.Error` a handle returns must be consumed by a matcher (or `consumeAllPendingErrors()`) or teardown fails the test. Teardown also restores each tracked store's `bindClock` binding to its value at first track (disposed stores skipped), so track a store BEFORE binding a test clock: a clock bound before the first track, or on an untracked store, is kept. A `StateTag.Secret` state's values are recorded as `Redacted`; value matchers on it throw a teaching error.

## Conventions

- Open an issue before submitting a PR (CONTRIBUTING.md) — undiscussed PRs may be closed.
- 0.x pre-stable; release version comes from the git tag via `-Pholdfast.version` (publish.yml), not from any committed file.
- Changelog: Keep-a-Changelog format; add entries under `## [Unreleased]` in `holdfast/CHANGELOG.md` (and per-module changelogs where they exist). Entries below 0.1.0 are a frozen internal design archive using old Vault naming — never rewrite them; same for `*-DESIGN.md` files.
- Mechanical renames go in two commits (file renames with no content changes, then content changes marked "(mechanical)") and the content commit's SHA gets appended to `.git-blame-ignore-revs`.
- API-mirroring docs updated in lockstep with public-API changes: root `README.md` modules table, `holdfast/README.md`, `holdfast/GUIDE.md` API-reference sections, module READMEs.
- Demo/sample apps live in the separate `vynatix/banking-demo` repo — don't add demos here.
