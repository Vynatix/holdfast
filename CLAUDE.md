# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Holdfast — transactional state containers for Kotlin Multiplatform (Maven group `com.vynatix`). Three-layer naming, all intentional: the **brand/repo/artifacts** are `holdfast*`, the **package** is `com.vynatix.holdfast`, but the **central class** is `Store<Self : Store<Self>>` (renamed Vault → Holdfast → Store; see `.git-blame-ignore-revs`). New code and docs use `Store*` class names; "holdfast" stays in artifact/package/brand names.

Targets: Android, JVM, iosArm64 + iosSimulatorArm64, wasmJs (wasmJs only on `:holdfast`, `:holdfast-coroutines`, `:holdfast-compose`). JDK 21, Kotlin 2.3.21, Gradle 9.5.

## Commands

```bash
./gradlew check                      # everything CI gates: tests, apiCheck, detekt, ktlintCheck
./gradlew :holdfast:jvmTest --tests "com.vynatix.holdfast.TransactionTest"   # one class
./gradlew :holdfast:jvmTest --tests "*.TransactionTest.someMethod"           # one method
./gradlew detekt ktlintCheck         # static analysis; format with: ./gradlew ktlintFormat
./gradlew :<module>:detektBaseline   # re-pin detekt baseline after deliberate cleanups
./gradlew apiDump                    # after ANY public-API change; commit <module>/api/* dumps
./gradlew :holdfast:dokkaGenerate    # docs (Dokka V2 — `dokkaHtml` no longer exists)
./gradlew publishToMavenLocal -Pholdfast.version=0.1.0
```

Per-target test tasks: `jvmTest`, `testAndroidHostTest` (AGP-KMP host-test naming — not `testDebugUnitTest`), `iosSimulatorArm64Test` (macOS host only). wasmJs test tasks are force-disabled on `:holdfast`/`:holdfast-coroutines` (tests use `runBlocking`/`newSingleThreadContext`, absent on wasm) and never run in CI.

Lint gotchas: detekt findings are baselined per module (`<module>/detekt-baseline.xml`) — rules stay active for new code. Files using K2 `context(name: Type)` syntax are excluded from ktlint (it can't parse them): `BoxedHandle.kt`; new context-parameter files need the same per-module `ktlint { filter { exclude(...) } }` treatment. Do NOT add `context(scope: CoroutineScope)` overloads next to default-param forms: inside any coroutine body the implicit `CoroutineScope` receiver satisfies the context parameter and silently captures the ambient scope (the `asStateFlow`/`bridge`/`suspendingBridge` overloads were removed for exactly this — issue #5).

CI (`.github/workflows/ci.yml`, push/PR to main) runs per module: `jvmTest` + `testAndroidHostTest` + `apiCheck` + `dokkaGenerate` + detekt/ktlint on ubuntu, `iosSimulatorArm64Test` + `jvmTest` on macos-15. **Known broken as written (verify before trusting/copying):** publish.yml calls `publishAndReleaseToMavenCentral` (vanniktech plugin — not applied anywhere; the build's own task is `publishAllPublicationsToSonatypeRepository`).

The hallmark modules (`:holdfast-hallmark`, `:holdfast-hallmark-coroutines`) are excluded from the default build because their `com.vynatix:hallmark*:0.1.0` deps only resolve via `mavenLocal()`. To include them, build/publish the sibling [hallmark repo](https://github.com/vynatix/hallmark) to `~/.m2` first, then run Gradle with `-Pholdfast.includeHallmark=true` (CI does exactly this). The `shouldBeBoxedAs` matcher lives in `:holdfast-hallmark`, not `:holdfast-testing`, for the same reason.

## Core architecture (`holdfast/src/commonMain/.../holdfast/`)

The unit of consistency is the transaction; everything below is contractual, not incidental:

- **States are declared eagerly, materialized lazily**: `val x by state { init }` declares `x` at construction through `StateDelegate.provideDelegate` (a `StateDeclaration` in the store's `StateRegistry`, in declaration order; no user code runs). The `MutableState` is materialized from the retained initializer on first need — first delegate read, `snapshot()` (which materializes every declared state, so snapshots are complete), `reset()` (likewise, before its transaction opens) or `restore()` (its targets, before its action opens). `properties`/`getState`/`hasState` show materialized states only; `removeState`/`clearStates` keep declared states' declarations, `dispose()` drops all. A name is declared once per store: a second declaration fails fast unless it re-runs the same site (same member `KProperty`, or a local delegated property of that name). A delegate wrapping `state(…)` must forward `provideDelegate` (see `BoxedHandleDelegate`). Initializers run behind a per-declaration latch outside `propertiesLock` (but under any lock their caller holds), read committed values only, may not write (`NoWriteRegion`: every write entrypoint throws), and cycles throw (`InitializerGraph`) instead of deadlocking; a throwing initializer stays retryable. `derived`/`suspendDerived` backings are `StateKind.DerivedBacking` (`registerDerivedBackingState`): captured by `snapshot()`, hidden from `stateNames`/`size`, restored only into the same instance (`originKey == lockOrderKey`).
- **`store action { }` buffers, never writes**: the whole action (including observer fanout) runs under the store's `transactionLock` (a reentrant spin-yield `StoreLock` — a slow observer blocks every other action on that store). `mutate` stages post-`Transformer.set` raw values into `Transaction.pendingWrites`. The owner thread gets read-your-own-writes through the savepoint chain (except inside a state initializer, which reads committed values only — or, re-run by `reset()`, its own store's reset values); other threads only ever see committed values. Nested actions are savepoints (inner commit merges into parent; outer rollback discards all).
- **Rollback never touches state and never re-runs `Transformer.set`** — load-bearing for asymmetric transformers (encryption). Same reason snapshots hold raw values, `restore()` goes through `stagePendingRaw` (re-routing it through `mutate` would double-encrypt), and `reset()` stages initializer output raw (initial values are stored without `Transformer.set`).
- **`reset()` (experimental, `Reset.kt`) re-runs retained initializers as one action** (id `Reset`; a savepoint inside an action, part of the frame inside `atomic`). It materializes every declared state first, then `stageResetOfDeclaredStates(txn)` installs a `ResetPass` on `Transaction.pendingReset` and resolves `StateKind.Declared` states in declaration order (derived backings and internal states are never reset; derived states recompute after the commit). A re-run initializer (`NoWriteRegion.runForReset`, no latch, under the reset's locks) reads its own store's declared states at their reset values via `ResetPass.valueFor` (fresh-store first-read order; a still-running one is a cycle) and everything else at committed values; it still may not write. Output is staged raw and only where it differs (`==`) from the transaction-visible value, so unchanged states never fire, even with `distinct = false`. `stageResetOfDeclaredStates` also stages straight into `atomic` frame roots (the #21 `reset(node)` shape); `ResetPass.addLiveKeyedEntries`/`notifyAttachments` are the PR 12/PR 10 extension points.
- **Snapshots leave memory through codecs; `restore` plans, then stages** (#20 R1; experimental except `StateCodec`). `StateCodec` (root, stable; `bridge.Codec` extends it) encodes a state's RAW value; it lives on `StateDeclaration.codec`, set only by the `@ExperimentalStoreApi` `state(transformer, distinct, codec, initialize)` overload — codec-less calls must keep resolving to the frozen 3-arg `state` (guarded by `StableStateOverloadTest`, in a no-opt-in file). `StoreSnapshot` wraps `CapturedContent` (raw values; `entry`/`get` by state instance, guarded by `originKey`) or `DecodedContent` (read by name through the reading state's codec); reads resolve through `MutableState.declaration` and work after dispose. The v1 wire body (`SnapshotEnvelope.kt`, embeddable verbatim) is canonical; the reader caps nesting at 64 and skips unknown fields; object values under `states` are reserved for keyed families. `RestorePlanner` runs BEFORE the action opens (materializes targets, runs codec `decode`, the type witness and `RestorePolicy`; the frozen 1-arg `restore` uses `IgnoreUnknown`); the action (id `Restore`) then throws any planned failure inside itself, or stages raw via `stagePendingRaw`, re-resolving each target (a concurrently dropped Declared target is re-materialized; a dropped derived backing is skipped). Equality is by value (captured vs captured, decoded vs decoded; `equalsEncodable` relates the two). No exception may carry a state value.
- **Every assignment of a committed value is write-bracketed** (`MutableState.writesBegun`/`writesEnded`, `ConsistentRead.kt`): the top-level apply pass opens the bracket on every state before assigning any and closes them all after (in a `finally`); `applyFromBridge` brackets its single write. `readConsistent` takes a lock-free cut that retries while a bracket is open or has moved and never blocks a writer — `snapshot()` uses it. A new path that assigns `currentValue` must bracket it, or snapshots can tear.
- **Commit fanout order is a contract**: observers → bridge publish → event drain. `:holdfast-coroutines`' `suspendAction` interposes between these phases via `@StoreInternalApi` hooks; reordering breaks it.
- **Writes into a closed transaction fail loudly** (#20 D16). After its apply pass a top-level commit stays installed through fanout; `Transaction.closedToWrites` (root applied, or this transaction or an ancestor ended) refuses writes: `mutate`/`update`/`emit` throw `IllegalStateException`, and a nested `action`/`atomic` returns `TransactionResult.Error` without running its body or middleware. "Nested" means on the owner thread or inside the commit (`Transaction.fanoutThreadId` for the sync window, `FanoutMarkers` for suspending commits); other threads' `action`/`atomic` wait. While a suspending holder is installed, `suspendingOwner` routes every thread's bare `mutate` into its transaction (joins before the apply pass, throws after). Every `pendingWrites` write goes through `pendingLock` (`Transaction.stagePendingWrite`).
- **Post-commit failures are never silent**: observer callbacks, fanout `Transformer.get`, bridge publishes and `derived` recompute failures go through `Store.internalReportUncaughtFailure` — `uncaughtObserverHandler` when set, else the `platform/UncaughtFailureLog` default (stderr on JVM/Android, stdout on iOS/wasmJs).
- **Middleware: last-registered is outermost** (its `started` fires first, `completed`/`error` last). `onTransactionCompleted` runs after the body but *before* commit — throwing there rolls back.
- **Bridges inbound (`applyFromBridge`) bypass transactions and middleware entirely** and deliberately don't re-publish (loop prevention). `mutate` outside an action synthesizes a one-shot action so middleware/observers always see committed semantics — except while a `suspendAction`/`suspendAtomic` holds the store (see the closed-transaction bullet).
- **`derived()` recomputes through `postCommit` and the internal, never-blocking `tryTopLevelAction`** (recomputing inline in the commit would mutate `pendingWrites` mid-iteration). Each derived submits ONE stable task and the queue dedups by identity, so N same-store sources in one commit recompute once; a source on another, idle store recomputes inline in that source's fanout, once per changed source. A busy host (active txn, or serializer/`transactionLock` taken) gets the task handed to its queue plus one retry — safe only because **every top-level holder drains after releasing** (canonical list: `Store.tryTopLevelAction` KDoc; a new holder must drain too, via `internalDrainPostCommitTasks`). `postCommit` re-reads `_activeTransaction` after enqueueing (lost-wakeup guard), and a drain pass runs each task instance once. `atomic(vararg stores)` is in-memory 2PC, lock-ordered by per-store `lockOrderKey`.
- **The cross-module boundary is `@StoreInternalApi`** (ERROR-level opt-in), not `internal` — companion modules opt in; everything public and *not* annotated is frozen by `apiCheck`. Every new public `Store` entrypoint must call `checkNotDisposed()` and get a row in `holdfast/src/commonTest/.../DisposedEntrypointTest.kt`; cold companion APIs (`asFlow`, `first`, …) check `isDisposed` before subscribing.
- **wasmJs is single-threaded by assumption**: `currentThreadId()` returns `0` for everyone there — any new thread-identity logic must tolerate this. Expect/actual pairs live in `platform/Threading`, `platform/FrameLocal` (frame- and fanout-marker slots), `platform/StoreThreadLocals` (the running-initializer slot `NoWriteRegion` reads; a plain global on wasmJs), `platform/UncaughtFailureLog` and `bridge/FileSystemKvStore`, plus `:holdfast-coroutines`' `FrameMarkerContext` (custom intermediate source sets `jvmAndAndroidMain`/`jvmAndAndroidHostTest` share JVM+Android actuals).
- `Store.Companion.defaultScope` is CAS-settable **once per process** — setting it in a test poisons every later test in that process.
- **`Store.clock` (`@ExperimentalStoreApi`) resolves like `scope`**: subclass getter override → `bindClock(Clock?)` binding → `Clock.System`. Store code reads time through `clock.now()`; library timestamps (`Transaction.endTime`, Timing/ProfilingMiddleware) deliberately don't. `bindClock` calls `checkNotDisposed()`; reading `clock` never throws.

Package layering: root kernel depends only on `platform`; `middleware/`, `bridge/`, `crypto/` are plug-ins over root contracts and never import each other. Grep trap: `middleware/HallmarkMiddleware.kt` contains `class ValidationMiddleware`. The public "vault" trio is renamed (`owningVault`→`owningStore`, `bindVault`→`bindStore`, `vaultTest`→`storeTest`); the old names survive as WARNING-level deprecated aliases for one minor — don't remove them early, and don't use them in new code. Remaining lowercase "vault" prose/internals are pre-rename residue.

## Testing harness (`:holdfast-testing`)

Entry point is `storeTest { }` (`vaultTest` is a deprecated alias; `holdfastTest` never existed — stale KDoc mentions it). Inside, `track(store)` (or an auto-registering extension used in scope, e.g. `store.read { }` / `store.timeline`; a bare `store.action { }` resolves to the `Store` member and does NOT auto-track) yields a `StoreHandle` exposing a `timeline` of `StoreEvent`s with infix matchers (`shouldFireInOrder`, `shouldHavePublished`, `shouldBeSuccess`/`shouldBeError`, …). Every `TransactionResult.Error` a handle returns must be consumed by a matcher (or `consumeAllPendingErrors()`) or teardown fails the test. Teardown also restores each tracked store's `bindClock` binding to its value at first track (disposed stores skipped), so track a store BEFORE binding a test clock: a clock bound before the first track, or on an untracked store, is kept.

## Conventions

- Open an issue before submitting a PR (CONTRIBUTING.md) — undiscussed PRs may be closed.
- 0.x pre-stable; release version comes from the git tag via `-Pholdfast.version` (publish.yml), not from any committed file.
- Changelog: Keep-a-Changelog format; add entries under `## [Unreleased]` in `holdfast/CHANGELOG.md` (and per-module changelogs where they exist). Entries below 0.1.0 are a frozen internal design archive using old Vault naming — never rewrite them; same for `*-DESIGN.md` files.
- Mechanical renames go in two commits (file renames with no content changes, then content changes marked "(mechanical)") and the content commit's SHA gets appended to `.git-blame-ignore-revs`.
- API-mirroring docs updated in lockstep with public-API changes: root `README.md` modules table, `holdfast/README.md`, `holdfast/GUIDE.md` API-reference sections, module READMEs.
- Demo/sample apps live in the separate `vynatix/banking-demo` repo — don't add demos here.
