# Validation Library 0.3.0 — Design (Aligned)

Source: grilling session 2026-05-03. 15 decisions, summarised below in answer order.

## Q1 — Library identity
**(B) Standalone KMP refinement-types library.** `:validation` is general-purpose; Vault is one consumer. Targeted at HTTP / form / parser / boundary use cases, not just Vault state validation.

## Q2 — Module split
**(ii) Two-module split → three modules total.**
- `:validation` — core, no Vault dep.
- `:validation-coroutines` — suspend extension (decided in Q10).
- `:holdfast-hallmark` — thin Vault adapter (decided in Q14).

Adopters not using Vault pull only `:validation`.

## Q3 — Error model
**(ε) Dual API.** `validate(P): HallmarkResult<O>` is the engine that accumulates violations; `infix of(P): O` is the throwing convenience built on top. `HallmarkResult` is sealed (`Success(value)` / `Failure(violations: NonEmptyList<Violation>)`). `HallmarkException : IllegalArgumentException` carries `violations`. No Arrow dep — rolling our own minimal `NonEmptyList<T>`.

## Q4 — Composite validation
**(β) Composite native, no reflection.** No `KProperty` types in the public API; users pass `(name: String, getter: (T) -> P)` pairs. Field-name and field-getter are decoupled — getters can be `{ it.email }` or `User::email` (auto-converted to `(User) -> String`, never used as a property reference).

## Q5 — Validator type structure (revised)
**Unified `Validator<IN, OUT>`** (revised from initial "two parallel hierarchies"). One interface; two builder paths:
- Leaf path: `BoxedValidator<P, O : Boxed<P>>` abstract base — `Boxed<P>` constraint enforced at this base.
- Composite path: `validator<T> { … }` DSL — produces `Validator<T, T>`.

Single `Field<T, OUT>` type, single `field(name, getter, validator)` factory in the composite DSL, polymorphic over any `Validator<IN, OUT>`.

## Q6 — Nested composites
**(β) Nested.** Composites can field-validate other composites. Violation paths thread automatically via `HallmarkResult.atPath(name)`. Collection validation (`each`/`forKey`/index notation) deferred to 1.1.

## Q7 — Violation shape
**(γ) Rich.**
```kotlin
data class Violation(
    val message: String,
    val path: List<String> = emptyList(),
    val code: String? = null,
    val rule: Rule<*>? = null,
    val args: Map<String, Any?> = emptyMap(),
)
```
`code` is the i18n / programmatic-handling key. `args` enables message templating. `rule` enables introspection in tests.

## Q8 — Rule shape
**(γ) Abstract class with metadata + `validate(): Boolean`.**
```kotlin
abstract class Rule<P>(val code: String, val messageTemplate: String) {
    abstract fun validate(value: P): Boolean
    open fun message(value: P): String = messageTemplate
    open fun args(value: P): Map<String, Any?> = emptyMap()
}
```
No `fun interface` (we lose ad-hoc `Rule { it > 0 }` SAM construction). Every rule is a named class — stronger introspection, named `code`s, override-able templating. Validator builds the `Violation` from rule metadata when `validate` returns false.

## Q9 — Spec / Condition layer
**(γ) Drop `Condition`, keep `Spec` with `SpecMode` enum.**
```kotlin
enum class SpecMode { ALL, ANY }

data class Spec<P, O : Boxed<P>>(
    val rules: List<Rule<P>>,
    val mode: SpecMode,
    val factory: (P) -> O,
)
```
`Spec` survives because multi-shape validation (Number = Int OR Float) is a real case. `Condition` was Boolean-combinator-only and didn't fit multi-error semantics. `RULE` type parameter falls off `Validator` — it was only used by `Condition`.

## Q10 — Async / suspend
**(δ) Sync core + `:validation-coroutines` extension module.** Mirrors the Vault architecture. Sync-only adopters don't pull `kotlinx-coroutines`. Async types live in `:validation-coroutines`: `SuspendRule<P>` (probably abstract class for parity), `SuspendValidator<IN, OUT>`, `suspendValidator<T> { … }` DSL, `SuspendBoxedValidator<P, O>` base, `SuspendValidatingTransformer` deferred until needed.

## Q11 — Composite DSL
**(β) Builder DSL block only.** `val UserValidator = validator<User> { field("email", { it.email }, EmailValidator) }`. No `compositeOf(...)` vararg shortcut. Conditional fields (`if (admin) field(...)`) work naturally.

## Q12 — Leaf declaration
**(α) Class-based.** Leaves are typically static; `object EmailValidator : BoxedValidator<String, Email>() { override val specs = … }` matches the existing pattern. The asymmetry with Q11 (composite is DSL) is defensible — leaves stay still, composites mutate fields conditionally.

## Q13 — Standard rules library
**(β) Common essentials.** ~14 rules in `:validation/Rules.kt` (or split by domain). Format-specific regexes (email, URL, UUID, IBAN, etc.) are NOT shipped — their canonical forms are debatable and ownership becomes a maintenance trap.

Set:
- String: `NonEmptyRule`, `NonBlankRule`, `LengthInRule(IntRange)`, `MinLengthRule(n)`, `MaxLengthRule(n)`, `MatchesRule(Regex)`, `StartsWithRule(prefix)`, `EndsWithRule(suffix)`
- Number (Comparable): `GtRule(n)`, `GteRule(n)`, `LtRule(n)`, `LteRule(n)`, `InRangeRule(range)`
- Collection: `NonEmptyCollectionRule`, `SizeInRule(min, max)`

## Q14 — Vault adapter scope
**(δ) Full ergonomic suite.** `:holdfast-hallmark` ships:
1. `ValidatingTransformer<P, O>(validator)` — Vault `Transformer<O>`.
2. `Holdfast.boxed(validator) { initial }` — state factory.
3. `BoxedCodec<P, O>(primitiveCodec, validator)` — `KvBridge`-compatible codec for `Boxed<P>` types.
4. `infix fun State<O>.assign(primitive: P)` — civilize-then-mutate sugar.

`EncryptingTransformer + ValidatingTransformer` chaining is a Vault-core gap (no transformer pipelining); document the limitation, don't try to fix it here.

## Q15 — Versioning
**(α) 0.2.0 → 0.3.0, hard break.** No deprecation shims. Pre-1.0 SemVer permits this. Adopter count of 0.2.0 is essentially zero. The 0.2.0 GAVs in `~/.m2` stay intact (no destructive cleanup).

## Final architecture

### `:validation` (com.vynatix:validation:0.3.0, package `com.vynatix.hallmark`)
**Types**:
- `Boxed<P>` — typed wrapper interface (carried over).
- `Rule<P>` — abstract class.
- `Violation` — data class.
- `HallmarkResult<O>` — sealed: `Success<O>(value)`, `Failure<O>(violations: NonEmptyList<Violation>)`.
- `NonEmptyList<T>` — minimal in-house non-empty list.
- `HallmarkException(violations)` — `IllegalArgumentException` subclass.
- `Spec<P, O : Boxed<P>>` — data class.
- `SpecMode` — enum.
- `Validator<IN, OUT>` — unified interface.
- `BoxedValidator<P, O : Boxed<P>>` — abstract base implementing `Validator<P, O>`.
- `Field<T, OUT>` — composite field (name + check lambda).
- `ValidatorBuilder<T>` — composite DSL builder.
- `validator<T> { … }` — top-level builder function.
- `Rules.kt` — 14 rule classes.
- `HallmarkResult.atPath(name)` — internal extension.

### `:validation-coroutines` (com.vynatix:validation-coroutines:0.3.0)
- `SuspendRule<P>` — suspend abstract class.
- `SuspendValidator<IN, OUT>` — suspend interface.
- `SuspendBoxedValidator<P, O>` — abstract base.
- `suspendValidator<T> { … }` — suspend composite DSL.
- Bridge: `SuspendValidator<IN, OUT>` accepts both sync and suspend sub-validators.

### `:holdfast-hallmark` (com.vynatix:holdfast-hallmark:0.3.0)
- `ValidatingTransformer<P, O>(validator)` — `Transformer<O>`.
- `Holdfast.boxed(validator) { initial }` — `StateDelegate<O>` factory.
- `BoxedCodec<P, O>(primitiveCodec, validator)` — `Codec<O>`.
- `infix fun State<O>.assign(primitive: P)` — civilize-and-mutate.

---

## Out of scope (deferred to 0.4.0+)

- Collection field validators (`each`, `forKey`, `[i]` path indices).
- `:holdfast-hallmark-coroutines` (Vault adapter for suspend validators / `suspendAction`).
- Format regex library (email, URL, UUID, IBAN — see Q13).
- i18n message resolver (consumers wire their own via `code` + `args`).
- Schema export / introspection (Konform-style).
- Transformer composition (`EncryptingTransformer + ValidatingTransformer` — Vault-core gap).
- Konform compatibility shim.

## Migration vs 0.2.0

Hard break. The 0.2.0 surface (`Civilizable`/`Validated`/`Boxed`, `Civilizer`/`Validator<P, R, O>`, `Variation`/`Spec` 3-param, `Condition`, `Factory`, `CivilizingTransformer`/`ValidatingTransformer` 3-param) is fully replaced. CHANGELOG documents the rewrite.
