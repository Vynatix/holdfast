# `:holdfast-coroutines` 2.0 — Design Record

Status: Design approved 2026-05-03. Implementation pending.
Scope: Single coordinated 2.0 across `:holdfast`, `:holdfast-coroutines`, `:holdfast-compose`, `:holdfast-hallmark`.

---

## 1. Library identity

`:holdfast-coroutines` 2.0 is a **coroutine-first peer of `:holdfast` core**, with full feature parity. Not a thin adapter (1.x positioning), not an MVI library. Suspending versions of every sync `:holdfast` capability where suspending semantically applies; transactional state container framing preserved.

The 1.x README ("Flow / StateFlow / suspend integration. Pulls in kotlinx-coroutines-core; nothing else.") is replaced. The new positioning matches `:holdfast` core's "transactional state" pitch, lifted into the suspending world: every async path retains the same all-or-nothing guarantee as the sync path.

---

## 2. Decision tree

| # | Decision | Choice | Consequence |
|---|---|---|---|
| Q1 | Library identity | Coroutine-first peer, full feature parity | Most original gap analysis items in scope; structural rework |
| Q2 | Scope ownership | Optional, lazily installed via `bindToScope(scope)` | Singleton `object Foo : Holdfast<Foo>()` pattern preserved |
| Q3 | Fallback policy | Tiered: per-call → per-holdfast `val` → global default; settable-once `defaultScope` | Compile-time-typed `CoroutineScope`, never null, no magic |
| Q4 | Middleware integration | `Middleware<V>` stays sync; opt-in `SuspendingMiddlewareHooks<V>` | One registry, opt-in async hooks, no migration |
| Q5 | Subscription semantics | Conflated state subscription via `MutableSharedFlow(replay=1, DROP_OLDEST)` | Producer never blocks; events use opposite policy |
| Q6 | Lifecycle | Two-tier — scope cancel = soft; `holdfast.dispose()` = terminal | Execution context separated from data structure |
| Q7 | Multi-vault concurrency | `suspendAtomic` sibling, deadlock-safe `lockOrderKey` ordering | Naming consistent with `suspendAction` |
| Q8 | Persistence | Both `Bridge<T>` (fire-and-forget) AND `SuspendingBridge<T>` (await-completion) | Sync action gets fire-and-forget; suspendAction awaits |
| Q9 | Events | `Eventful<E>` interface + `EventfulHoldfast<Self, E>` base, atomic with commit | Transactional events stronger than peer MVI libraries |
| Q10 | Rollout | Single bundled 2.0, no flags, no deprecation cycle | One migration cliff |
| Q11 | Suspending parity | Ship `suspendDerived`; skip `suspendComputed` and `SuspendingTransformer` | Pure transformers, computed stays sync |
| Q12 | Subscription API | Promote `effect` from `Holdfast<Self>`-member-extension to top-level `State<T>`-extension | Cast leak removed; no new public method |
| Q13 | Hot StateFlow API | Drop `EagerStateFlow`; `asStateFlow(started=Eagerly)` is the replacement | One hot Flow API, scope-managed disposal |
| Q14 | Targets | Android + iOS + JVM; defer JS/Wasm/native-non-iOS | `jvmAndAndroidMain` intermediate source set |
| Q15 | API style | Default-param AND K2 context-param overloads side-by-side | ~6 extra signatures across 3 APIs |

## 3. Architectural areas

### 3.1 Scope ownership and lifecycle (Q2 + Q3 + Q6)

`Holdfast<Self>` gains a `scope: CoroutineScope` property. Three resolution levels, each compile-time-typed:

```kotlin
abstract class Holdfast<Self : Holdfast<Self>> {
    open val scope: CoroutineScope get() = Companion.defaultScope

    fun bindToScope(scope: CoroutineScope)
    fun dispose()

    companion object {
        private val customDefaultScope = atomic<CoroutineScope?>(null)

        var defaultScope: CoroutineScope
            get() = customDefaultScope.value ?: lazyProcessScope
            set(value) {
                check(customDefaultScope.compareAndSet(null, value)) {
                    "Holdfast.defaultScope is settable-once; it has already been assigned."
                }
            }
    }
}

private val lazyProcessScope: CoroutineScope by lazy {
    CoroutineScope(SupervisorJob() + Dispatchers.Default + CoroutineName("VaultProcessScope"))
}
```

**Resolution order** for any scope-using API:
1. Per-call: explicit `scope` parameter at call site.
2. Per-vault: `override val scope` in the vault subclass.
3. Global: `Holdfast.defaultScope`, lazily defaulting to a process `SupervisorJob`.

**Settable-once `defaultScope`**: the global accepts at most one explicit assignment. Reads of the lazy default do **not** freeze the value — only an explicit set does. Reassignment after the first explicit set throws. App-init pattern:

```kotlin
val appScope = CoroutineScope(SupervisorJob() + Dispatchers.Default)
Holdfast.defaultScope = appScope
```

**`bindToScope(scope)`**: replaces the bound scope reference for one holdfast. Optional. Calling on an already-bound vault rebinds (per Q6 D rebindable semantics).

**Lifecycle two-tier:**

| Trigger | Effect on in-flight `suspendAction` | Effect on hot subscriptions | Effect on sync API | Recovery |
|---|---|---|---|---|
| Bound scope cancels | `CancellationException` → existing rollback path | Complete normally | Unaffected; falls back to `Holdfast.defaultScope` | `bindToScope(newScope)` reactivates |
| `holdfast.dispose()` | Same rollback; subsequent calls throw `IllegalStateException("holdfast disposed")` | Complete normally | Throws `IllegalStateException` | None — terminal |

`holdfast.dispose()` is idempotent. It clears states, detaches bridges, clears observers, terminates events SharedFlow. The bound scope is *not* cancelled (caller owns its lifecycle).

**Cold APIs that don't need scope** — `asFlow`, `first`, `awaitValue`, `suspendAction`, `suspendAtomic` — work on disposed-but-not-cancelled-state vaults via caller's coroutine context. They throw on disposed vaults via the same `IllegalStateException`.

### 3.2 Subscription semantics (Q5 + Q12 + Q13)

**Conflated state subscription** is the single contract for `State<T>` observation:

```kotlin
fun <T : Any> State<T>.asFlow(): Flow<T> = flow {
    val shared = MutableSharedFlow<T>(
        replay = 1,
        extraBufferCapacity = 0,
        onBufferOverflow = BufferOverflow.DROP_OLDEST,
    )
    shared.tryEmit(value)
    val disposable = this@asFlow effect { shared.tryEmit(this) }
    try { emitAll(shared) } finally { disposable.dispose() }
}
```

Producer-side `tryEmit` always succeeds (replay slot atomically overwritten), so commit-thread never blocks on a slow collector. Latest value is always recoverable from the replay buffer.

**`effect` is the canonical subscription API**. Promoted from `Holdfast<Self>`-member-extension to top-level `State<T>`-extension:

```kotlin
infix fun <T : Any> State<T>.effect(handler: T.() -> Unit): Disposable
```

`MutableState<T>.observe` becomes `internal`. Both prior call sites collapse:

```kotlin
val disposable = state effect { value = this }
```

Existing `vault { state effect { ... } }` continues to compile — the vault block now provides DSL context but doesn't own the `effect` resolution.

**Single hot StateFlow API**:

```kotlin
fun <T : Any> State<T>.asStateFlow(
    scope: CoroutineScope = owningScope,
    started: SharingStarted = SharingStarted.WhileSubscribed(),
): StateFlow<T>

context(scope: CoroutineScope)
fun <T : Any> State<T>.asStateFlow(
    started: SharingStarted = SharingStarted.WhileSubscribed(),
): StateFlow<T>
```

`owningScope` is `internal val State<T>.owningScope: CoroutineScope get() = (this as MutableState<T>).owningVault.scope` — the cast is package-internal, never in published signatures.

`EagerStateFlow<T>` and `asEagerStateFlow()` are removed. Migration: `asStateFlow(started = SharingStarted.Eagerly)`. Disposal handled by scope cancellation.

### 3.3 Middleware (Q4)

`Middleware<V>` stays sync. New opt-in interface for async hooks:

```kotlin
interface SuspendingMiddlewareHooks<V : Holdfast<V>> {
    suspend fun onTransactionStartedAsync(context: MiddlewareContext<V>) {}
    suspend fun onTransactionCompletedAsync(context: MiddlewareContext<V>) {}
    suspend fun onTransactionErrorAsync(context: MiddlewareContext<V>, error: Throwable) {}
}
```

A middleware can implement either or both. **Concentric-ring ordering** within `suspendAction`:

```
chain order forward:    sync started → async started → body
chain order backward:   body → async completed → sync completed
on error:               body throws → async error → sync error (per middleware, reverse chain order)
```

`runCatching` wraps each hook invocation; one middleware's failure does not abort others.

Blocking `action` invokes sync hooks only (suspending hooks are invisible to it). Document this clearly: a middleware that implements *only* `SuspendingMiddlewareHooks` will be silent under sync `action`.

The fix to the documented "no middleware support" limitation in 1.1 is part of this: `suspendAction` runs the chain. Sync hooks always fire on the suspending path.

### 3.4 Multi-vault concurrency (Q7)

```kotlin
suspend fun <R> suspendAtomic(
    vararg vaults: Holdfast<*>,
    body: suspend () -> R,
): TransactionResult<R>
```

Implementation contract:

- Vaults sorted by `Holdfast.lockOrderKey` (existing rule); deadlock-safe across any combination.
- Each vault's `AsyncSerializer.Mutex` (same as `suspendAction` uses) is acquired in order via `withLock`. Mutually exclusive with blocking `atomic` and per-holdfast `action`/`suspendAction` on the same vault.
- Body runs in caller's coroutine context. No vault scope dependency.
- On body return: commit each vault's root transaction in lock order, sequential per-holdfast observer/bridge/event fanout.
- On body throw or `CancellationException`: rollback all in reverse lock order, release locks, rethrow.
- Commit phase wrapped in `withContext(NonCancellable)`; partial-commit cannot happen.
- Nested `suspendAtomic`: each vault's Mutex is reentrant for the same coroutine owner. Nested call's overlapping vaults reuse the existing lock.
- `vault.action { }` and `vault.suspendAction { }` inside body become savepoints of the vault's root transaction.

### 3.5 Persistence (Q8)

**`SuspendingKvStore`** interface for async backends (DataStore, SQLDelight, Realm):

```kotlin
interface SuspendingKvStore {
    suspend fun get(key: String): String?
    suspend fun put(key: String, value: String)
    suspend fun remove(key: String)
    suspend fun snapshot(): Map<String, String>
}
```

**Two bridge factories** on the same store:

```kotlin
fun <T : Any> SuspendingKvStore.bridge(
    key: String,
    codec: Codec<T>,
    scope: CoroutineScope = Holdfast.defaultScope,
): Bridge<T>

fun <T : Any> SuspendingKvStore.suspendingBridge(
    key: String,
    codec: Codec<T>,
    scope: CoroutineScope = Holdfast.defaultScope,
): SuspendingBridge<T>

context(scope: CoroutineScope)
fun <T : Any> SuspendingKvStore.bridge(key: String, codec: Codec<T>): Bridge<T>

context(scope: CoroutineScope)
fun <T : Any> SuspendingKvStore.suspendingBridge(key: String, codec: Codec<T>): SuspendingBridge<T>
```

**`Bridge<T>`** (fire-and-forget): conflated save channel via `Channel(Channel.CONFLATED)`, async load on observe attach. `errors: SharedFlow<Throwable>` exposed for failure visibility (replay=0, extraBufferCapacity=16, no implicit collection).

**`SuspendingBridge<T> : Bridge<T>`** (await-completion):

```kotlin
interface SuspendingBridge<T : Any> : Bridge<T> {
    suspend fun publishAwaited(value: T)
    override fun publish(value: T): Boolean    // default: scope.launch { publishAwaited(value) }
}
```

`:holdfast-coroutines` overrides `suspendAction`'s commit phase to detect `SuspendingBridge` via `is`-check and call `publishAwaited` sequentially in `NonCancellable`. Sync `action` uses the default `Bridge.publish` (fire-and-forget). Document loudly: same bridge yields different semantics in sync vs suspending action contexts — caller picks the action type to pick the persistence guarantee.

**Companion implementations to ship**:
- `InMemorySuspendingKvStore` for tests (with `delay(0)` between operations).
- `SuspendingFileSystemKvStore` (expect/actual on Android+JVM+iOS) using `withContext(Dispatchers.IO)` for file ops.

### 3.6 Events (Q9)

`Eventful<E>` is an opt-in capability marker:

```kotlin
interface Eventful<E : Any> {
    val events: SharedFlow<E>

    @VaultActionDsl
    fun emit(event: E)
}
```

**`EventfulHoldfast<Self, E>`** is the canonical implementation. Vaults extend it instead of `Holdfast<Self>`:

```kotlin
abstract class EventfulHoldfast<Self : EventfulHoldfast<Self, E>, E : Any>(
    extraBufferCapacity: Int = 16,
    onBufferOverflow: BufferOverflow = BufferOverflow.SUSPEND,
) : Holdfast<Self>(), Eventful<E> {
    private val _events = MutableSharedFlow<E>(0, extraBufferCapacity, onBufferOverflow)
    final override val events: SharedFlow<E> = _events.asSharedFlow()

    final override fun emit(event: E) {
        val txn = activeTransaction
            ?: error("Eventful.emit must be called inside action or suspendAction")
        txn.stagePendingEvent(_events, event)
    }
}
```

**`EventfulSupport<E>`** is the helper for vaults that can't extend `EventfulHoldfast` (e.g., already extending another base). Same staging machinery, exposed as a delegate field.

**Atomic with commit**: events stage into `Transaction.pendingEvents: MutableList<Pair<MutableSharedFlow<*>, Any>>`. On commit, each pending event is forwarded to its channel's `tryEmit` after state observers fire and bridges publish, before `commit()` returns. On rollback, the list is discarded.

**Lossless** (`extraBufferCapacity = 16`, `BUFFER_OVERFLOW.SUSPEND`, `replay = 0`): producer suspends if no collector keeps up. Configurable per channel at declaration.

**Single event type per vault**. Multiple variants via a sealed `E`.

**Off-action emit throws** `IllegalStateException`. Same enforcement style as `mutate` outside action.

**Commit-phase ordering** (universal):
1. State observers fire (post-`transformer.get`).
2. Bridges publish (sync `Bridge.publish`; for SuspendingBridge under `suspendAction`, `publishAwaited` is awaited).
3. Events `tryEmit` to their `MutableSharedFlow`.

Inverting any of these would race against user expectations. Subscribers to `events` always see "saved" *after* `state` observers see the new state.

### 3.7 Suspending parity scope (Q11)

| Sync API | Suspending peer in 2.0? | Notes |
|---|---|---|
| `action` | `suspendAction` ✓ | 1.1; now invokes middleware (Q4) |
| `atomic` | `suspendAtomic` ✓ | Q7 |
| `Bridge<T>` | `SuspendingBridge<T>` ✓ | Q8 |
| `KvStore` | `SuspendingKvStore` ✓ | Q8 |
| `Middleware<V>` | `SuspendingMiddlewareHooks<V>` ✓ | Q4 |
| `derived(sources, compute)` | `suspendDerived(...)` ✓ | Recompute via `vault.scope.launch { ... }` and internal `suspendAction` |
| `computed(compute)` | — | Read-time eager; `state.value` semantics break under suspension |
| `Transformer<T>` | — | Pure-function contract; suspension breaks rollback safety guarantee |

**`suspendDerived`** signature:

```kotlin
fun <V : Holdfast<V>, T : Any> V.suspendDerived(
    vararg sources: State<*>,
    compute: suspend V.() -> T,
): Pair<State<T>, Disposable>
```

Recompute path uses `vault.scope.launch { compute() }` with `internal_suspendAction` to stage the result. Reuses existing `postCommitTasks` queue. Cancellation of `vault.scope` cancels in-flight compute calls; the disposable cancels source subscription.

### 3.8 API style (Q15)

Two parallel signatures per scope-using API:

```kotlin
// Default-param style:
fun <T : Any> State<T>.asStateFlow(
    scope: CoroutineScope = owningScope,
    started: SharingStarted = SharingStarted.WhileSubscribed(),
): StateFlow<T>

// K2 context-param overload:
context(scope: CoroutineScope)
fun <T : Any> State<T>.asStateFlow(
    started: SharingStarted = SharingStarted.WhileSubscribed(),
): StateFlow<T>
```

**Scope-using APIs receiving the dual-style treatment** (~3 APIs, ~6 signatures total):
- `State<T>.asStateFlow`
- `SuspendingKvStore.bridge`
- `SuspendingKvStore.suspendingBridge`

Other APIs do not need overloads — scope is implicit via vault binding (`suspendAction`, `suspendAtomic`, `events`, `suspendDerived`) or caller's coroutine context (`asFlow`, `first`, `awaitValue`).

**Internal use of context parameters** is unconstrained — the dual-style decision applies only to *published* signatures.

## 4. Load-bearing core changes

Two new `@VaultInternalApi` extension hooks in `:holdfast` core:

### 4.1 `MutableState.applyCommittedRaw(value)`

Today's `applyCommitted` does three things:
1. Replace stored value
2. Fire observers
3. Call `bridge?.publish(value)`

The new internal API splits step 3 out:

```kotlin
@VaultInternalApi
fun applyCommittedRaw(value: T)    // does (1) and (2), skips bridge

internal fun applyCommitted(value: T) {
    applyCommittedRaw(value)
    bridge?.publish(value)
}
```

Why: `:holdfast-coroutines`'s `suspendAction` commit phase needs to interpose between observer fanout and bridge publish to handle `SuspendingBridge.publishAwaited`. Without `applyCommittedRaw`, the only path involves either double-firing the bridge or duplicating observer-fanout logic in `:holdfast-coroutines`.

### 4.2 `Transaction.stagePendingEvent(channel, event)`

New per-transaction buffer alongside `pendingWrites`:

```kotlin
internal val pendingEvents: MutableList<Pair<MutableSharedFlow<*>, Any>>

@VaultInternalApi
fun stagePendingEvent(channel: MutableSharedFlow<*>, event: Any)
```

On commit (after observer fanout, after bridge publish), each pending event is `tryEmit`-ted to its channel. On rollback, the list is discarded. On nested commit, merged into parent's `pendingEvents`.

## 5. Behavior changes (no flag, ship as fixes)

### 5.1 `asFlow()` is now lossless-conflated

**Was**: `callbackFlow { trySend(value) }` with default `BUFFERED` capacity. Under fast emitter / slow collector, `trySend` returns false past 64 backlog, **values silently drop**.

**Now**: backed by `MutableSharedFlow(replay=1, extraBufferCapacity=0, onBufferOverflow=DROP_OLDEST)`. Latest value always available via replay slot. Producer never blocks; conflation is *the documented contract*.

This is a strict improvement. No flag. CHANGELOG entry: "Fixed: asFlow() no longer silently drops values under contention. Conflation is now explicit; if you relied on every commit being delivered to a slow collector, that was always broken — use vault.events for discrete event streams instead."

### 5.2 `suspendAction` now invokes the `Middleware<V>` chain

**Was**: GUIDE §14.8 documented "no middleware support" as a `suspendAction` limitation. Logging, timing, validation middleware silently no-op'd on the async path.

**Now**: `suspendAction` runs the middleware chain. Sync hooks always fire. Middleware that implements `SuspendingMiddlewareHooks` additionally fires async hooks.

Strict improvement. Document loudly in CHANGELOG: middleware authors who relied on "suspendAction won't trigger me" must verify their hooks are idempotent / safe under the suspending path.

## 7. Rollout strategy (Q10)

Single bundled 2.0 across `:holdfast`, `:holdfast-coroutines`, `:holdfast-compose`, `:holdfast-hallmark`. Coordinated CHANGELOG. Simultaneous version bump on all four modules. ABI golden file regenerated; `apiCheck` passes against fresh baseline.

No feature flags. Two behavior changes (§5.1, §5.2) ship as fixes — they were never *intended* behaviors worth preserving.

No deprecation cycle. `EagerStateFlow`, `EagerStateFlow.dispose()`, `asEagerStateFlow()` removed in 2.0. Migration is one mechanical rewrite per call site (§6).

   - `InMemorySuspendingKvStore`, `SuspendingFileSystemKvStore`
5. **Events** (Q9)
   - `Eventful<E>` interface
   - `EventfulHoldfast<Self, E>` base, `EventfulSupport<E>` helper
   - `@VaultInternalApi Transaction.stagePendingEvent`
   - Commit-phase ordering: observers → bridges → events
6. **Multi-vault and derived parity** (Q7/Q11)
   - `suspendAtomic`
   - `suspendDerived`
7. **Platform expansion** (Q14)
   - `jvmAndAndroidMain` intermediate source set
   - JVM target on all four modules
   - CI matrix: macos-15 + ubuntu-latest
8. **API style** (Q15)
   - K2 context-param overloads on `asStateFlow`, `bridge`, `suspendingBridge`
   - ABI golden file regenerated

## 10. Open implementation tactics (not architectural)

These do not fork the design. Choose during implementation.

- **Test framework**: kotlin.test + kotlinx.coroutines.test + Turbine. All three. Public test helper `vaultTest { ... }` that owns a `TestScope`.
- **`Holdfast.defaultScope` thread-safety**: backed by an `atomic<CoroutineScope?>`; settable-once enforced via `customDefaultScope.compareAndSet(null, value)` — the first explicit assignment wins, subsequent assignments throw. Reads return the lazy process scope until an assignment lands; reading does not prevent a future assignment.
- **`SuspendingKvBridge.errors` collection**: `extraBufferCapacity = 16`, `replay = 0`, no implicit collection; document that callers attach their own collector for critical persistence.
- **Per-vault scope override expression timing**: prefer `override val scope: CoroutineScope get() = ...` (getter) over `override val scope: CoroutineScope = ...` (val) in singleton vaults to avoid lazy-init order traps.
- **Event subscriber dispatch**: `MutableSharedFlow.tryEmit` synchronously invokes ready collectors. Document subscribers should `flowOn(Dispatchers.Main.immediate)` for UI consumers, or apply `.buffer()` for slow ones.
- **`suspendAtomic` observer fanout**: per-holdfast sequential, not cross-vault parallel. Same as sync `atomic`. Document as intentional.

## Appendix B: Key tradeoffs preserved through grilling

These were considered and rejected. Document for future maintainers who re-encounter them.

- **Mandatory scope at construction** (Q2 b): rejected. Breaks the `object Foo : Holdfast<Foo>()` singleton pattern that GUIDE actively endorses.
- **Throw on unbound vault** (Q3 i): rejected. Loses default-fallback constraint.
- **Hard-coded process default** (Q3 iii): rejected. Magic; unconfigurable.
- **Phantom-type `Bound`/`Unbound` vault** (Q3 F): rejected. Breaks singleton pattern.
- **Lift `observe` to `State<T>` interface** (initial Q12): rejected. Creates redundancy with `effect`.
- **Generic `Holdfast<Self, E>`** (Q9 i): rejected. Breaks every existing vault subclass.
- **Delegated event property `val events by events<E>()`** (Q9 iii): rejected. Property declaration vs capability marker mismatch.
- **Fire-immediately events** (Q9 β): rejected. Loses transactional rollback guarantee — entire pitch of vault.
- **Lossless state subscription** (Q5 b): rejected. Slow subscriber back-pressures commit thread; liveness disaster.
- **Buffered-with-bounded-loss state subscription** (Q5 c): rejected. Silent drop of older values; same footgun in different clothes.
- **Incremental 1.x minors** (Q10 b): rejected. Multiple migration cliffs for the same underlying redesign.
- **Hybrid 1.2-with-flags + 2.0-flips-defaults** (Q10 c): rejected. Flag debt for behavior changes that were never intended in the first place.
- **Ship `suspendComputed`** (Q11 sub-b A): rejected. `SuspendingState<T>` doesn't compose with `effect`/`bridge`/`mutate`.
- **Ship `SuspendingTransformer`** (Q11 sub-c A): rejected. Transformer purity is documented contract; suspension breaks rollback safety.
- **Keep `EagerStateFlow` deprecated** (Q13 b): rejected. Conflicts with single-2.0-cliff strategy.
- **Add JS/Wasm targets** (Q14 D/E): rejected for 2.0. Single-threaded execution breaks Threading semantics; deferred to demand-driven minor.
- **Default-param only for new APIs** (Q15 a): rejected. Compile-time-strict scope is a real benefit for some users; ship dual-style for day-one availability.
